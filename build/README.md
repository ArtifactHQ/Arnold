# Arnold build system

Generates per-tool plugin / skill artifacts from one canonical source (`skills/`) so Arnold can ship natively to Claude Code, Cursor, and Codex (as marketplaces) and to Codex / Antigravity / Windsurf / Gemini CLI (via `scripts/install.sh` or the agentic [`INSTALL.md`](../INSTALL.md) procedure) without maintaining parallel source trees.

## Quick start

```bash
make build          # build all five targets
make verify         # build twice, diff hashes, confirm deterministic
make clean          # remove dist/
```

## What gets built

| Target | Output path | Source transforms |
| --- | --- | --- |
| `make claude` | `dist/claude-plugin/` | None — `skills/` copied verbatim; `.claude-plugin/` manifests copied verbatim. Submit-ready. |
| `make cursor` | `dist/cursor-plugin/` | `.cursor-plugin/plugin.json` generated; SKILL.md `name: arnold:X` → `arnold-X`; frontmatter strips `argument-hint`/`allowed-tools`/`user-invocable`; `arnold-rules/SKILL.md` → `rules/arnold-rules.mdc` with `alwaysApply: false`. |
| `make codex-plugin` | `dist/codex-plugin/` | Codex user-global plugin. `.codex-plugin/plugin.json` generated; short-named `skills/<n>/` (the plugin namespaces under `arnold`); frontmatter `name: arnold:X` → `X`; same frontmatter strip as Cursor; `AGENTS.md` synthesized from `CLAUDE.md`. |
| `make codex` | `dist/codex-skills/` | Codex project-scoped skills. Copied to `.agents/skills/arnold-<name>/SKILL.md` (plural path); same frontmatter strip; `AGENTS.md` synthesized from `CLAUDE.md`. |
| `make antigravity` | `dist/antigravity-skills/` | Copied to `.agent/skills/arnold-<name>/SKILL.md` (**singular** `.agent` — distinct from Codex). Same frontmatter strip. |

`dist/` is gitignored. It is always regenerated by the release pipeline before publishing.

## Design invariants

- **Single source of truth.** `skills/*/SKILL.md` is canonical. Everything under `dist/` is a function of `skills/`. Never edit `dist/` by hand.
- **Deterministic.** Two consecutive builds produce byte-identical output. `make verify` exercises this. mtimes in `dist/` are pinned to the source file mtime.
- **No runtime dependencies.** Stdlib-only Python 3. No `pip install` required. This matters because the build runs on contributors' machines, in CI, and on release workflows — any of which may be a fresh checkout.
- **No network calls.** Build reads `skills/`, writes `dist/`. That is all.
- **Frontmatter parser is minimal.** It understands the subset of YAML that Arnold SKILL.md files actually use (simple key-value, multi-line list values). If a richer YAML construct is ever needed, extend the parser; do not add a YAML dependency.

## Adding a new target

1. Write a `build_<name>()` function in `build/build.py`. Follow the pattern of the existing four: clean the target dir, build it, pin mtimes.
2. Add `<name>` to the `TARGETS` dict.
3. Add `<name>` to `_resolve_dir()`.
4. Add a `make <name>` target to the `Makefile`.
5. Run `make verify` — the new target must pass the determinism check.

## Adding a new frontmatter transform

If a target needs to strip or rename additional frontmatter fields, the pattern is:

```python
strip_keys = {"argument-hint", "allowed-tools", "user-invocable", "new-field-to-strip"}
# ...
if key == "name":
    new_entries.append((key, value.replace(":", "-")))  # or other transform
```

The `split_frontmatter` / `emit_frontmatter` helpers preserve key order and body content, so transforms compose cleanly.

## Release pipeline

Not yet automated. First releases use a documented manual checklist; automation lands after the manual flow proves out.

When CI is wired up, the basic shape is:

```
on: tag v*
  - make clean && make build && make verify
  - publish dist/claude-plugin/ to Claude Code marketplace
  - publish dist/cursor-plugin/ to Cursor marketplace
  - publish dist/codex-skills/ to Codex (mechanism TBD)
  - publish dist/antigravity-skills/ to Antigravity (mechanism TBD)
```
