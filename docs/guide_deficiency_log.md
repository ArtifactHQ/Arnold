| 1 | Phase 1 — `fetch_results` | Followed the guide skeleton to iterate over the `tasks` array passed by the engine and filter by `task.external_id` | The guide does not mention that the `TierExecutionEngine` sync path passes **stale** in-memory task objects to `fetch_results`. Async providers avoid this because `await_results` calls `tasks.map(&:reload)`. Providers are never called directly by the engine — the engine calls `executor.call()`, which filters unpublished tasks, calls `provider.create_tasks`, and does the `find_by` + update.
